Use case: ui-mockup.
Create ONE high-fidelity desktop application screenshot, landscape 16:10, approximately 1600x1000, sharp legible UI text, straight-on with no monitor/device mockup or perspective. This is a proposed redesign for Loomlight, a visual novel authoring app, not a marketing page.
Keep the shared app shell restrained: top bar “Loomlight” and project “The Last Tram”, left navigation Story, Source, Branches, Characters (selected), Lorebook, Assets, Variables, Settings. A compact searchable Characters list contains Bec (In game), Mara (Planning only, selected), Eli (In game), Station manager (Planning only). One fixed “+ New character” button at the top-right workspace header in every concept.
Selected character “Mara”, small “Planning only” badge, subtitle “Station attendant · night shift”. Game setup belongs to this same character, with explicit Create game character and Link existing character actions in a compact game-status area; never imply card text automatically changes the game.
Shared fixed bottom editor bar reads “Unsaved changes”, “Discard”, and one primary “Save changes” button. Do not add another global Save or numerous AI buttons. Character switching does not move the workspace frame or these actions.
The user dislikes sprawling forms, huge empty textareas, visual hierarchy with everything equally important, cluttered relationships and the confusing title “Story links & knowledge notes”. Essentials are description, personality, motivations and voice; secondary information is optional. Replace that confusing group with plain distinct labels “What they know”, “Linked lore”, “Where to use these notes” when needed; do not show all advanced fields by default.
Use short public fictional prose: “A station attendant who remembers every passenger.” Personality “Reserved, observant, quietly protective.” Motivation “Keep everyone safely on their way.” Voice “Short sentences, gentle humour.” Relationship “Bec — Wary of the station manager.” Author-written knowledge note “Recognises the passenger, but keeps it quiet.”
Readable system sans typography, compact native creative-tool controls, generous but purposeful whitespace, clear selection, modest corners, restrained borders. No giant decorative title, lorem ipsum, raw UUIDs, metadata tables, dangling Missing Scene warnings, hamburger admin dashboard, approval toolbar, stars/ratings/charts or infinite canvas. No logos from other products. Show the design, not annotations about the design.
LAYOUT A: A quiet writing notebook inspired by prose-first writing tools, not a form.
Light paper/ivory surfaces with deep teal accents and warm gray app navigation. Slim searchable cast list about 220px wide beside the 150px app nav. Main area is one comfortable editorial document, about 650px wide, with the fixed Mara identity header and a two-tab “Writing” (selected) / “Game setup” switch above it.
Write directly on the page with lightly separated text sections, NOT large outlined input boxes. “At a glance” is the short description, then “Personality”, “Motivations”, “Voice” with concise paragraphs and visible editing caret in one paragraph. Headings have clear hierarchy; text area is calm, like an editable notebook.
A narrow right “On this page” rail lists these four sections. Below the rail a small “More details” area has collapsed rows Appearance & background, Relationships · 1, What they know, Linked lore, Where to use these notes. Relationships is one concise summary row, not a stack of selectors and textareas. Small initials avatar M only, no portrait or decorative illustration. Game setup actions may appear as a small optional status block in the right rail. Center the actual writing; avoid a giant unused lower half. Fixed save bar.
